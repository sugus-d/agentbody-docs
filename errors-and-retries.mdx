---
title: "Error handling and retries"
description: "Handle failed AgentBody Gateway API requests safely."
---

Treat every non-success response as actionable. Use the status code, response headers, and error schema defined in the [API reference](/api-reference/introduction) to decide whether to retry, correct a request, or contact support.

## Retry only transient failures

Retry only failures that the canonical API contract identifies as transient. Use exponential backoff with jitter, and respect any retry or rate-limit headers returned by the Gateway.

Do not retry invalid requests unchanged. For authentication, validation, or authorization failures, correct the underlying configuration or input before sending another request.

## Preserve request context

Log the operation, status code, and a safe correlation value where available. Do not log API keys, authorization headers, request secrets, or sensitive request bodies.

## Keep retries bounded

Set a maximum retry count and an overall timeout for each workflow. When a request still fails after the allowed attempts, surface a clear error to the caller and investigate the response using the API contract.

<Note>
  The Gateway-owned OpenAPI artifact is authoritative for supported status codes, error formats, pagination behavior, and rate-limit headers.
</Note>
